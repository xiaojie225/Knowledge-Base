# 微信小程序 - 简单题

## 1. 微信小程序的生命周期有哪些？请描述每个生命周期的作用

**答案**：
微信小程序页面生命周期包括：onLoad、onShow、onReady、onHide、onUnload。

onLoad：页面加载时触发，只执行一次，适合初始化页面数据，获取路由参数。

onShow：页面显示时触发，可能执行多次，适合从其他页面返回时刷新数据。

onReady：页面初次渲染完成时触发，只执行一次，适合操作DOM元素或Canvas。

onHide：页面隐藏时触发，比如跳转到其他页面或按Home键，适合暂停定时器等。

onUnload：页面卸载时触发，适合清理定时器、监听器等资源。

## 2. wx.setStorageSync和wx.setStorage的区别是什么？

**答案**：
wx.setStorageSync是同步存储，会阻塞主线程直到存储完成，适合少量数据。

wx.setStorage是异步存储，不会阻塞主线程，适合大量数据。

在实际开发中，小程序页面加载时会频繁调用存储操作，如果使用同步方法可能影响页面性能。对于关键数据（如用户token），建议使用同步存储确保数据一致性；对于大量用户行为记录，建议使用异步存储。

## 3. 小程序页面间传参有哪些方式？

**答案**：
1. URL参数：wx.navigateTo({url: 'path?key=value'})，适合传递简单数据，但长度有限制。
2. 全局数据：通过getApp().globalData传递，适合多个页面共享的数据。
3. 本地存储：wx.setStorageSync存储，适合需要持久化的数据。
4. EventChannel：页面间通信，适合父子页面关系。
5. 自定义事件：通过自定义事件总线实现。

实际开发中，用户信息通常存储在本地存储或全局数据，而页面跳转参数主要用于传递临时标识，如商品ID、订单号等。

## 4. 如何处理小程序的异步操作？

**答案**：
小程序异步操作主要通过Promise、async/await、回调函数三种方式。

Promise方式：将wx.request封装成Promise，避免回调地狱。

async/await方式：代码更易读，适合复杂逻辑。

回调函数：微信原生API都是回调方式，但容易嵌套过深。

实际开发中，建议统一封装API请求，使用Promise或async/await，同时结合错误处理和loading状态，提升用户体验。


## 6. wx.navigateTo和wx.switchTab的区别是什么？

**答案**：
wx.navigateTo：跳转到非tabBar页面，保留当前页面栈，可以返回，最多10层。

wx.switchTab：跳转到tabBar页面，关闭所有非tabBar页面，不能携带参数。

实际开发中，用户中心、首页等通常配置为tabBar页面，使用switchTab跳转；而详情页、编辑页等普通页面使用navigateTo跳转。

## 7. 如何实现微信授权登录？

**答案**：
1. 使用wx.getUserProfile获取用户头像、昵称等基本信息。
2. 使用wx.login获取登录code。
3. 将code和用户信息发送到后端，后端调用微信API换取session_key。
4. 后端生成token返回给小程序。
5. 小程序保存token到本地存储，后续请求携带token。

实际开发中，需要注意微信授权策略的变化，比如2021年后getUserProfile替换了getUserInfo，并且每次都需要用户主动授权。

## 8. 小程序如何获取用户手机号？

**答案**：
1. 使用button组件，设置open-type="getPhoneNumber"。
2. 绑定bindgetphonenumber事件。
3. 用户授权后，事件回调中包含加密的encryptedData和iv。
4. 将encryptedData、iv和登录code发送到后端。
5. 后端使用session_key解密获取手机号。

实际开发中，用户可能拒绝授权，需要提供跳过选项，但不能强制要求授权手机号。

## 10. 小程序网络请求如何统一封装？

**答案**：
在app.js中封装_post和_get方法，统一处理请求头、参数、错误。

核心逻辑：
1. 自动添加token、wxapp_id等公共参数。
2. 统一处理loading状态。
3. 统一处理错误响应（code为-1时重新登录，code为0时显示错误信息）。
4. 支持success、fail、complete回调。

实际开发中，还可以封装重试机制、请求取消、接口mock等功能，提升开发效率和用户体验。

## 11. 小程序如何实现表单验证？

**答案**：
小程序表单验证主要通过前端验证和后端验证。

前端验证：在表单提交前检查必填项、格式等。

if (!nickname || nickname.trim() === '') {
  wx.showModal({
    title: '提示',
    content: '请输入昵称'
  });
  return;
}

后端验证：提交到后端后，后端再次验证，确保数据安全性。

实际开发中，前端验证提升用户体验，后端验证保证数据安全，两者缺一不可。

## 12. 如何实现小程序的图片上传？

**答案**：
使用wx.uploadFile上传图片。

核心步骤：
1. 选择图片或获取临时头像。
2. 调用wx.uploadFile上传到服务器。
3. 上传成功后，服务器返回图片的URL。
4. 保存URL到本地或提交到数据库。

实际开发中，需要处理上传进度、失败重试、图片压缩等。对于头像上传，还可以使用微信的chooseAvatar组件直接获取头像。

## 13. 小程序如何处理页面数据更新？

**答案**：
使用this.setData更新页面数据。

this.setData({
  avatarUrl: newAvatar,
  name: newName
});

注意事项：
1. 不要直接修改this.data，必须通过setData。
2. setData是异步的，不要在setData后立即使用this.data。
3. 尽量减少setData调用次数，合并更新多个字段。
4. 避免setData更新整个对象，只更新变化的字段。

实际开发中，频繁的setData会影响性能，特别是在列表滚动时，需要优化更新策略。

## 14. 如何实现小程序的全局状态管理？

**答案**：
1. 使用getApp().globalData定义全局变量。
2. 在页面中通过getApp()访问和修改全局数据。
3. 结合本地存储实现持久化。

实际开发中，如果项目复杂，可以使用类似Redux的状态管理方案，或者使用小程序的behaviors实现跨页面逻辑复用。对于简单项目，globalData+本地存储足够使用。

## 15. 如何优化小程序的用户体验？

**答案**：
1. 加载状态：在请求时显示loading，提升用户感知。
2. 错误提示：友好的错误提示，而不是冷冰冰的错误码。
3. 数据缓存：减少重复请求，提升响应速度。
4. 分步引导：复杂流程分解为多个步骤，降低用户认知负担。
5. 取消支持：用户可以随时取消操作，避免被卡住。

实际开发中，需要从用户角度思考每个交互细节，比如登录流程中，用户取消授权后应该怎么办，是强制要求还是提供跳过选项。

**4. 小程序的 wxss 和 css 有什么区别？**

答：
- wxss 支持 rpx 单位（响应式像素）
- wxss 支持 @import 导入样式
- wxss 不支持某些 CSS3 选择器
- wxss 有尺寸单位换算（1rpx = 0.5px）

**11. 小程序登录流程是怎样的？**

答：
1. 调用 wx.login() 获取临时登录凭证 code
2. 将 code 发送到开发者服务器
3. 开发者服务器调用 auth.code2Session 接口，换取 openid 和 session_key
4. 开发者服务器生成自定义登录态，返回给小程序
5. 小程序存储登录态，用于后续请求

```javascript
wx.login({
  success(res) {
    wx.request({
      url: 'https://api.example.com/login',
      data: { code: res.code },
      success(response) {
        wx.setStorageSync('token', response.data.token)
      }
    })
  }
})
```

**14. wxs 是什么？有什么作用？**

答：WXS（WeiXin Script）是小程序的一套脚本语言，可以在 WXML 中使用。
- 用于视图层的数据处理
- 提高渲染性能（不需要和逻辑层通信）
- 语法类似 JavaScript

```xml
<wxs module="m1">
  var msg = "hello world"
  function toLower(str) {
    return str
  }
  module.exports.toLower = toLower
</wxs>

<view>{{m1.toLower("HELLO")}}</view>
```

**19. 小程序支付流程是怎样的？**

答：
1. 小程序调用 wx.login() 获取 code
2. 后端用 code 换取 openid
3. 后端统一下单（调用微信支付API），获取预支付 prepay_id
4. 后端返回支付参数给小程序
5. 小程序调用 wx.requestPayment() 发起支付
6. 用户完成支付
7. 微信回调后端支付结果
8. 后端处理业务逻辑

```javascript
// 前端发起支付
wx.requestPayment({
  timeStamp: '',
  nonceStr: '',
  package: '',
  signType: 'MD5',
  paySign: '',
  success(res) {
    console.log('支付成功')
  },
  fail(res) {
    console.log('支付失败')
  }
})
```
